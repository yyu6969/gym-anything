The main command is:

```bash
gym-anything
```

A second binary, `gym-anything-extras`, dispatches to optional
research and infrastructure tools that live alongside the library.
See [Extras](/extras) for what's available.

## `gym-anything run`

Run one environment, optionally with a task.

Examples:

```bash
gym-anything run moodle --task enroll_student -i
gym-anything run benchmarks/cua_world/environments/moodle_env --task enroll_student --output-dir /path/to/output
```

Important flags:

- `--task`: task id to load
- `-i`, `--interactive`: keep the environment alive for interactive use
- `--steps`: number of steps in non-interactive mode
- `--seed`: reset seed
- `--open-vnc`: open a VNC viewer in interactive mode
- `--output-dir`: canonical root for recordings and run-specific state

<Callout type="info">
If you pass a short environment name such as `moodle`, the CLI resolves it against `benchmarks/cua_world/environments/`. If you don't pass `--task`, the CLI picks a random task from that environment.
</Callout>

## `gym-anything benchmark`

Run an agent on benchmark tasks. This is the main way to evaluate agents.

Single task:

```bash
gym-anything benchmark moodle --task enroll_student --agent ClaudeAgent --model claude-opus-4 --output-dir /path/to/output
```

All tasks in an environment:

```bash
gym-anything benchmark moodle --agent ClaudeAgent --model claude-opus-4 --split test
```

Full corpus:

```bash
gym-anything benchmark all --agent ClaudeAgent --model claude-opus-4 --split test
```

Important flags:

- `--agent` (required): agent class name (e.g. `ClaudeAgent`)
- `--task`: task ID. Omit to run all tasks in the split (batch mode)
- `--model`: model identifier (e.g. `claude-opus-4`)
- `--output-dir`: canonical root for episode artifacts, agent runs, model dumps,
  and run-specific state
- `--steps`: max steps per task (default: 50)
- `--split`: task split for batch mode (default: `test`). Use `disk` to run every task folder on disk, ignoring split files
- `--parallel`, `--jobs`: batch task processes to run at once
- `--max-tasks`: limit the number of tasks in batch mode
- `--fast-io`: construct the environment with `fast_io=True`
- `--disable-thinking`: request non-thinking mode from OpenAI-compatible VLM
  servers via `chat_template_kwargs.enable_thinking=false`
- `--post-reset-observation-delay`: seconds to wait after `env.reset` before
  the first model observation
- `--post-step-observation-delay`: seconds to wait after each `env.step` before
  refreshing the observation that goes to the next model turn
- `--timing-jsonl`: choose the per-iteration timing log path for a single-task
  run; relative paths are beneath `--output-dir`, and absolute paths must also
  stay beneath it. Otherwise the log is written under the episode directory
- `--semantic_traj_apply PATH`: enforce a semantic trajectory JSON for a
  `Gemini3Agent` single-task run; only the active semantic step is exposed to
  the agent, and the existing task verifier still decides PASS/FAIL
- `--agent-arg KEY=VALUE`: extra agent argument (repeatable)
- `--remote-url`: route environment execution through a remote master or worker
- `--remote-timeout`: HTTP timeout for remote calls
- `--remote-worker-reset-policy`: worker-local reset policy, usually `core`
- `--verifier-mode`: override `task.json` verifier mode for the run, for example `vlm_checklist`
- `--vlm-checklist-model`: model used by the VLM checklist verifier

<Callout type="info">
When `--task` is omitted, the CLI enters batch mode and runs all tasks for the given environment and split. Each task runs in its own process for fault isolation.
</Callout>

## Runtime output layout

Both `run` and `benchmark` resolve one output root in this order:

1. `--output-dir`
2. `GYM_ANYTHING_OUTPUT_DIR`
3. `$XDG_STATE_HOME/gym-anything`, or `~/.local/state/gym-anything`

Relative explicit paths are resolved against the invocation working directory.
Benchmark definitions remain in the benchmark package or source checkout and
are never copied into the output root.

Runtime components retain their existing internal names beneath the root:

```text
<output-dir>/
  artifacts/             # episode recordings, trajectories, and summaries
  all_runs/              # reference-agent observations and responses
  model_usage_dumps/     # provider usage objects, when emitted
  log_dumps_claude/      # raw Claude responses, when emitted
  state/                 # local monitoring state
  work/                  # ephemeral dependency work, when needed
```

Heavyweight reusable caches are machine-level and do not change when
`--output-dir` changes. Their precedence is:

1. the component-specific variable;
2. `GYM_ANYTHING_CACHE_DIR` plus the component subdirectory;
3. the stable machine-cache default.

| Cache | Component-specific variable | Default |
| --- | --- | --- |
| QEMU base images and checkpoints | `GYM_ANYTHING_QEMU_CACHE` | `~/.cache/gym-anything/qemu` |
| Gym-managed Apptainer SIFs | `GYM_ANYTHING_APPTAINER_CACHE` | `~/.cache/gym-anything/apptainer` |
| AVD checkpoints | `GYM_ANYTHING_AVD_CHECKPOINT_CACHE` | `~/.cache/gym-anything/avd-checkpoints` |
| AVD container images | `GYM_ANYTHING_AVD_CONTAINER_CACHE` | `~/.cache/gym-anything/containers` |
| Agent sandbox images | `GYM_ANYTHING_AGENT_SANDBOX_CACHE` | `~/.cache/gym-anything/agent-sandbox` |
| Remote downloads | `GYM_ANYTHING_REMOTE_CACHE` | `~/.gym_anything_cache` |
| Sandweave installation/assets | `SANDWEAVE_HOME` | `~/.cache/gym-anything/sandweave` |

Gym supplies a shared machine default for `SANDWEAVE_HOME` so Sandweave does
not fall back to a CWD-local project installation. An explicitly configured
`SANDWEAVE_HOME` still wins.

`GYM_ANYTHING_QEMU_WORK_DIR` remains an explicit override for disposable QEMU
overlays; without it, Gym retains its historical `<QEMU cache>/work` location.
Fast-I/O work uses `GYM_ANYTHING_FAST_IO_WORK_DIR`, then the system temporary
directory when usable. `SANDWEAVE_LOCAL_DIR` is run-specific and defaults to
`<output-dir>/work/sandweave-local`. Apptainer's own blob cache continues to
honor `APPTAINER_CACHEDIR`; Gym does not overwrite it.

Remote benchmark example:

```bash
gym-anything benchmark moodle \
  --task enroll_student \
  --agent ClaudeAgent \
  --model claude-opus-4 \
  --remote-url http://master-host:5800
```

Verifier overrides can also be set with environment variables. CLI flags take precedence over environment variables, which take precedence over `task.json`.

```bash
GYM_ANYTHING_VERIFIER_MODE=vlm_checklist \
GYM_ANYTHING_VLM_CHECKLIST_MODEL=gemini-3-flash-preview \
gym-anything benchmark moodle --agent ClaudeAgent --model claude-opus-4
```

Common checklist verifier environment variables:

- `GYM_ANYTHING_VERIFIER_MODE`
- `GYM_ANYTHING_VLM_CHECKLIST_MODEL`
- `GYM_ANYTHING_VLM_CHECKLIST_BACKEND` such as `gemini`, `local`, `openai`, or `anthropic`
- `GYM_ANYTHING_VLM_CHECKLIST_BASE_URL`
- `GYM_ANYTHING_VLM_CHECKLIST_TEMPERATURE`
- `GYM_ANYTHING_VLM_CHECKLIST_MAX_FRAMES`
- `GYM_ANYTHING_VLM_CHECKLIST_COMPLETION_THRESHOLD`
- `GYM_ANYTHING_VLM_CHECKLIST_INTEGRITY_THRESHOLD`

## `gym-anything agents`

List available agent implementations.

```bash
gym-anything agents
```

<Callout type="info">
Use this to see which agent names you can pass to `gym-anything benchmark --agent`.
</Callout>

## `gym-anything list`

List available environments.

Examples:

```bash
gym-anything list
gym-anything list --verbose
```

`--verbose` also prints the tasks under each environment.

Check host prerequisites and optional verifier imports.

gym-anything doctor

Useful flags:

- `--runner`: limit the report to one runner
- `--verification-root`: check verifier imports under a specific root

## `gym-anything compatibility`

Show the runner compatibility matrix.

Examples:

```bash
gym-anything compatibility
gym-anything compatibility --runner docker
gym-anything compatibility --json
```

## `gym-anything validate`

Validate one environment and its task specs.

Example:

```bash
gym-anything validate moodle --task enroll_student
```

This is the lighter spec check.

## `gym-anything verify spec`

Verify one environment directory and its task specs in more detail.

Example:

```bash
gym-anything verify spec moodle --task enroll_student
```

Useful flag:

- `--json`

This is the more detailed spec verification path.

## `gym-anything verify corpus`

Verify all environment and task specs under a root.

Examples:

```bash
gym-anything verify corpus
gym-anything verify corpus benchmarks/cua_world/environments --max-failures 100
```

Useful flags:

- `--max-failures`
- `--write-status-manifest`
- `--write-verified-split`
- `--write-missing-hook-manifest`
- `--json`

The default root is `benchmarks/cua_world/environments`.

## `gym-anything verify task`

Run a task through reset and finalization, then execute its final check.

Example:

```bash
gym-anything verify task moodle --task enroll_student
```

Useful flags:

- `--seed`
- `--use_cache`
- `--cache_level`
- `--use_savevm`
- `--json`
